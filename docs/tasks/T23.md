# T23 · Verify GitHub contracts on dedicated sandbox scale sets

**Depends on:** T09, [T11](T11.md) and an approved isolated GitHub target with one-job test executors. **Baseline:** the real pinned SDK is covered by scripted transports. No target-service behavior is established by these fixtures. [GitHub contract and release gates](../implementation-plan.md#11-verification-gates-and-decisions-for-review)

## Prerequisites

Record the exact GitHub product/host and version or feature flags, separate test repo/runner groups/set IDs, unique labels, client and runner pins, sandbox-only credential owner, test workflows, cleanup responsibility and approved operation window. Verify that production workflow labels and sessions cannot be reached. Use managed secret references and sanitized IDs. Never capture registration input, PATs, session URLs, exchanged tokens or job payloads. Obtain approval for mutating tests on disposable resources.

Use the T11-integrated bootstrap on an authorised disposable executor for the JIT and completed-job cases. This test can use one supported execution path or a separately provisioned sandbox executor before the full T24 and T25 backend canaries. Record exactly which one-job path was exercised. Keep unverified backend-specific isolation and cleanup gated independently.

## Integration harness

Add a Go suite under `tests/integration/` with `//go:build integration`. Run with `go test -tags=integration ./tests/integration/... -count=1`, explicit `SCALESET_INTEGRATION_CONFIRM=sandbox`, and an approved run manifest with allowed GitHub scope/set IDs and AWS account/Region/resource IDs as applicable. Credentials come from approved runtime identity and secret references, with no raw credential flags. Validate the manifest and caller/target identity before enabling any mutation. Missing, conflicting or production targets abort before write. Require separate explicit opt-in for replacement, destructive cleanup or restore scenarios. Bound runtime and resources and emit a sanitized result ledger with owned resource IDs and cleanup state. Ordinary CI exercises guard and fixture logic without a live opt-in.

Run the scoped GitHub harness as soon as T09 and T11 plus a disposable one-job executor are ready. The ASG/Fargate canary suites extend the same manifest and reporting conventions. Use synthetic, uniquely labelled jobs and sanitized test records. Report skipped/unobservable service cases as unverified.

## Runbook and evidence

| Test | Procedure | Evidence and acceptance |
| --- | --- | --- |
| Enterprise PAT and GitHub App | Resolve correct enterprise group/name/ID using a classic enterprise PAT and a separate supported App scope. Exercise existing and explicit-create cases only on disposable names. Run an exact label selector workflow with one JIT runner through completion. | Sanitized target, scope and API outcomes, one scoped JIT and completed workflow link. Record classic PAT policy, required privileges, SSO if applicable and selected TTL/rotation owner. Wrong scope/group, policy, expiry and revoked token reject. GHES labels or GHE.com routing are only supported where verified. |
| Exclusivity and rotation | Open a session under an exact owner. Exercise a conflicting open in the isolated set and a credential candidate lookup. Rotate the secret through a safe shutdown/start boundary and inject an invalid candidate. | No overlapping acquiring sessions. Existing valid credential survives rejected candidate. New session processes a delivery and JIT before the old PAT is revoked. Record usable remote absence/closure evidence. |
| Delivery and acknowledgement | Exercise initial stats, message ID zero where available, cursor advancement, empty poll, redelivery and dropped response after remote deletion. Distinguish missing/forbidden session and the exact retry outcome. | Durable inbox/facts and cursor trace linked to ordered provider observations. No duplicate acquisition and no inferred ack/absence from an unqualified 404. If the service cannot supply a case, record offline coverage and the live limitation separately. |
| Assignment and acquisition | Offer multiple identified requests under unchanged aggregate statistics, restart in between, observe successful, rejected, omitted and uncertain outcomes and their subsequent assignments/terminal events. Compare exact requests with current-snapshot ordering. | Correlated proof is required before a reserved ID can be released based on assignment. Aggregate increases, unrelated requests, absent responses and lagging stats cannot release it. Unknown semantics keep conservative accounting. |
| Drain and zero capacity | Start with configured warm reserve, enter drain while work is queued/running, validate the transmitted max-capacity value and the service’s behavior with zero. | New acquisition stops, assigned jobs continue and no idle reserve launches. Header observation alone does not prove remote suppression. Record a qualified fallback if the service still sends offers. |
| Scheduling fence | Choose a disposable already registered runner. Exercise the relevant removal/fencing operation when idle, after dispatch before start is observed, and while executing. Preserve admitted jobs and independently record scheduling outcome. | Require evidence that a verified fence prevents new scheduling or refuses removal for assigned/busy runners before permitting automated retirement. If unavailable, keep idle runners protected and use the approved drain process. |
| Ambiguous writes | Inside approval, interrupt the response to creation/session/JIT calls after a test-side commit. Observe exact sent calls and remote readback or operator evidence. | One wire attempt where required. Record what readback establishes and what it cannot prove. No competing session, second mint or blind recreation. |

## Exit criteria

Publish an evidence table with expected/observed outcomes, target and dates, sanitized trace IDs, links and explicit gated capabilities. Verify conformance with `go test -race ./tests/sdkcontract` and `make check` before credentialed tests. Mark unobservable cases unverified and retain fail-closed behavior. Never authorize cleanup from a runner reference alone. Capture a session and credential recovery runbook and reclaim only approved disposable resources after confirming quiescence.

Link each result to its gate: enterprise App/PAT target and rotation enable the matching `githubsets` connection, ordered exact request attribution enables assignment-based release in `lifecycle/delivery.go`, live zero-capacity behavior informs the draining listener, and the dispatch-before-start case gates connected-idle retirement in `reconciler`. Validate the pinned SDK's session inspection surface and document operator recovery for an orphaned session if no authoritative list or inspection is available. Lost ack and ambiguous closure keep their existing fail-closed ledger transitions until verified.
