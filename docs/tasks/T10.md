## Boundaries and state

Reconciliation takes a validated profile, applied configuration generation and digest, current lease, and a normalized provider snapshot. Reuse `Coordinator.Reconcile`, its planner output, the executor classifier and current-session demand. Keep SDK types in provider adapters. The plan may identify a resource candidate. Dispatch needs an exact allocation, provider resource ID and incarnation, the current evidence supporting the action, and a canonical action and request digest. A plan can be reused for reporting. Its authorization cannot survive a changed lease, binding, resource, job, runner state or provider precondition.

Use the existing `OP#<intent>` and `EFFECTS` records and revision/fence checks. Once executing, an effect owns its target until durable readback resolves it. Provider evidence returns a definitive applied outcome, definitive absence subject to provider deadlines, or an unresolved outcome. An API request that was accepted is not proof that the resource is now terminal. For shutdown, distinguish a cancelled-before-dispatch intent from a request that may have reached the provider. For restart, process outstanding effects before considering new proposals. Do not reconstruct missing immutable request fields from a newer generation.

Keep listener long polls and delivery acks independent of slow provider calls. Serialize mutators per profile and explicitly coordinate shared ledger revisions when admission, observations and dispatch are concurrent. At the dispatch boundary require reread and compare-and-set against the authorization evidence, or a design that makes the same race impossible. Mark what a DynamoDB transaction can fence and what must be checked at the external provider. Track backend outage, unresolved effect, unknown capacity and current time-to-deadline independently.

## T10c storage and recovery contract

`Store.apply` supports fenced puts today. Add a revision-checked transactional delete for the derived active index, preserving unique keys in each request and counting the lease check and delete operations against the DynamoDB transaction limit. Keep existing `OP#<intent>` and `EFFECTS` records. In the same transaction, create the profile's `ACTIVE-OP#<index-generation>#<intent>` marker when an effect becomes unfinished and delete it on settlement. Store only the intent key, expected identity and retry/scheduling metadata needed to reconcile. Read the exact `OP#` row and check its revision before acting. Keep the existing count payload readable by older controllers. If index completeness or count disagrees, hold mutations and revalidate.

Use a strongly read, revisioned per-profile `EFFECT-REBUILD` record to store index generation, owner epoch, last processed sort key, progress/count and completion. New-format writers maintain the index atomically. Only reuse a completed generation after proving continuity from the previous lease and writer protocol. Record the writer protocol with lease acquisition/renewal and retain previous-owner lineage for this check. Unknown or older writers, incomplete generations and index/count mismatch invalidate the shortcut. Merely observing a current-epoch counter from an older writer is insufficient. If the lease changed during an incomplete rebuild, resume only with proven continuity while journal writes were frozen, otherwise start a new generation.

Check downgrade separately from index recovery. An older binary may ignore and drop new fields when rewriting a row, and cannot recover the new replay or handoff states. Block its activation through the deployment/ownership preflight while those states are outstanding or the bindings no longer match. Keep retained new-format wire state available for recovery and exercise an approved downgrade after clean quiescence.

Rebuild an untrusted index from strongly consistent `OP#` pages with new journal mutations closed for that profile. Read at most 32 source rows per page and two pages per scheduling pass. Atomically write active markers and the page checkpoint under the current lease and expected rebuild revision. Keep rebuild output private to the candidate generation until the final fenced transaction publishes completion and the verified count. A partial generation never serves absence or dispatch decisions. On response loss read back the checkpoint. Remove obsolete derived markers in bounded batches after publication. With trusted continuity, normal restart enumerates the active prefix without scanning settled history. Existing effect data remains recoverable after rollback, even if an old binary did not maintain the new index.

Schedule a bounded active-work page per eligible profile in rotation and limit account-wide concurrency. Use the existing deployment-wide `due` index only as an optional wake-up hint. Recheck keys strongly, coalesce duplicate signals and ensure an empty or stale index cannot starve a profile. Test an interrupted rebuild in 10,000 retained effects and two profiles with unequal backlogs. Assert page and read budgets and eventual progress, followed by steady-state recovery that reads no settled `OP#` rows.

Allow expiry only through a verified terminal/settled transition after the replay and incident-review retention horizon. Protect catalog, session, demand, admission/count, active markers, claims, leases, unresolved effects and nonterminal executors from TTL. Where expiry could forget a dispatched effect ID or reused allocation, retain a durable deduplication fence. A cancel-before-dispatch can rearm and is not equivalent to an irreversible terminal outcome. Test physically present expired rows and ensure TTL never authorizes cleanup or reexecution.

## T10c durable effect envelope

Extend `Effect` with an explicitly versioned, canonical **nonsecret** request, its digest, the initiating generation and an exact target/identity. Include allocation, provider resource and incarnation as applicable. Retain the attempt epoch and deadline separately from the first possible send and optional provider replay deadline. Commit the immutable request and earliest possible send before the first provider call. Validate the digest at delivery and every retry. Older rows lack a replayable body. Keep strong readback and operator recovery available, and never synthesize a replay from newer config or unverified inferred defaults. Store no credential or JIT payload here.

The journal distinguishes provably undispatched cancellation, confirmed application, definitive rejection tied to this exact attempt, and absence established after the applicable deadline. A status code alone cannot prove rejection. A failed replay or an error from a later attempt cannot erase an earlier ambiguous send. Preserve unresolved effects and count until the whole operation is resolved. Allow a new lease-scoped attempt only for a provider operation with a verified idempotency window, exact request/token match, active ownership and time remaining for the attempt before that window. Retain the original first-send bound across renewals and restarts. Non-idempotent writes do not gain this transition.

## T10d dispatch and admission

For each candidate, strongly reread current lease and catalog, unfinished work, exact allocation and runner/job/resource/process revisions, then refresh relevant provider preconditions. Persist or reuse the immutable plan. Run the durable begin transition with the lease, effect and applicable input revisions as conditions. Only the winning attempt with confirmed begin receipt may send. Acquire and refresh the bounded request context before send, and recheck cancellation and dispatch deadline. Provider identity, external ownership and scheduling fences require separate checks. A database condition does not atomically fence AWS or GitHub. Apply readback outcomes using the saved operation and current revision.

Project a verified, fresh result into `listener.Capacity` for the same profile, current session, generation and lease epoch. `Maximum` is the effective limit. `OutsideAssigned` counts all occupied slots except those with exact evidence they are already counted in this current assigned sample. Queued jobs, aggregate assigned counts and unmatched running jobs provide no such evidence. Count uncertain, unretired, unassigned idle and uncorrelated pending slots conservatively. Until a link is verified, subtract the slot in full. Unmapped running, stale or partial inputs, recovering ownership or an unfinished conflicting effect keep admission closed. Once wired, the listener rechecks current revisions after polling and before reserving or dispatching. Avoid holding a mutex across provider I/O.

Test cap 10 with 8 assigned, including 2 matched busy, and 2 unknown executors. OutsideAssigned is 2 and no new requests may be acquired. Test a known zero maximum, overflow/invalid counts, stale snapshots, mismatched session and duplicate correlated slots. Keep the existing durable reservation subtraction. Test simultaneous `PersistDelivery` and `ObserveResource` against one allocation under `-race`. For a revision conflict, reread and recompute the narrow transition with bounded attempts, preserving the other writer's facts and acknowledgement deadline. Exhaustion defers processing/replay and never acknowledges an unpersisted delivery.

Record exact durable handoff state on the executor or an atomically associated record. `unused` requires proof that no offer was ever released or that revocation excluded consumption, plus fresh exact resource evidence and no contrary runner or job facts. Expiry, missing offer and ambiguous consume cannot prove unused. A terminal Fargate task consumes no live slot, but unresolved job or registration state still needs separate recovery.

## T10e shared ownership and drain

Move the current listener-local heartbeat and final lease release to the root runtime coordination boundary. One owner publishes the latest immutable lease snapshot to listener, reconciliation, handoff and event workers and cancels their mutation contexts on confirmed loss or expiry before another dispatch. Keep a bounded heartbeat during graceful shutdown while draining current operations. Stop admission and new dispatch, cancel polls, join workers, cancel all provably unstarted effects, close owned sessions, verify remaining effects and release only when quiesced. Any remote ambiguity leaves recoverable durable state. A recovering owner observes and settles existing work but does not start new side effects.

Drain progresses from serving existing assignments with zero reserve to two separated authoritative clear passes, then to a durably recorded closure intent and exact session close. Use a closure hold scoped to the current binding and drain generation. Restart or credential rotation must honor the hold and must not open a competing session. Recheck the final pass's freshness, pending deliveries, reservations, unfinished effects, nonterminal owned executors and active/ambiguous handoffs with strong bounded reads before tombstoning. Discover offers through verified allocation/principal bindings in the profile, without a deployment-wide scan. Include a fresh AWS check and proof that retained ASG floor instances cannot receive jobs. Preserve permissions until the deployment preflight also verifies this state. A missing post-close demand sample is not a zero; rely on still-valid clear evidence plus the verified no-new-admission/routing boundary, otherwise block removal.

Keep immutable bindings strict in v1. Model eligible replacements as a new profile with distinct claims and route traffic only through the reviewed migration/drain sequence. A replacement requiring reuse of the same claimed remote identity needs explicit ownership transfer or owner handback. Incrementing a generation cannot move that claim automatically.

## Safety decisions

- A cleanup candidate is advisory until the executor and its incarnation are reverified under current ownership. Authorize a completed executor only with exact job completion, matched one-job process exit and log-flush grace under the current classifier. For unused or dead executors require verified no released handoff, atomic revocation, or authoritative terminal evidence as applicable. Missing observations, stale demand, contradictory facts and an unverified active/idle state must never become permission to terminate.
- Retiring connected idle runners requires the independently proven GitHub scheduling fence in [T23](T23.md). Until then, preserve them and report the drain blocker. Handle an ASG floor through verified unregistered parked capacity under the group owner's control, with separate runner and physical capacity accounting.
- Stop new dispatch during shutdown or ownership loss. Cancel polls and join mutators within their deadlines. Release only after confirmed closure and quiescence. On unclean takeover, restrict the process to observation and recovery until there is positive host fencing and settled remote outcomes.
- Use strongly consistent current-session demand for planning. Revalidate capacity before admission. Unknown backend limits and unfinished effects must block new work. Track the inability to locate an unfinished operation as degraded and keep mutations closed.

## Failure and restart matrix

| Boundary or fault | Required durable and external outcome |
| --- | --- |
| Crash before intent | No provider call and no pending effect. Next healthy pass may plan from current evidence. |
| Intent committed, before durable begin | Planned intent remains. Re-read evidence and either safely cancel or rearm under the new owner rules. Zero provider calls from the interrupted attempt. |
| Begin committed, before response to the controller | Work is potentially dispatched even if the journal's response was lost. Require provider evidence before reusing capacity or rearming. |
| Provider accepted, response dropped | Preserve executing/uncertain effect and stable target. No competing write, including after lease transfer. Rediscover through the adapter and settle with exact evidence. |
| Provider terminal evidence persisted, response to ledger write dropped | Subsequent reads find the terminal effect. Settle idempotently and leave the unfinished count exact. |
| Stale lease or expired attempt | No new dispatch. Test both DynamoDB fencing and cooperative worker cancellation. The successor remains in recovery if the old process can call either remote service. |
| Fresh conflicting job/process evidence or changed incarnation before dispatch | Reject or cancel the old candidate without sending cleanup. Preserve protection and log the nonsecret identity and reason. |
| Due index omits work or repeats stale pages | Base-table evidence keeps the profile closed. Work discovery can resume in bounded passes and cannot starve behind settled history or another profile's backlog. |
