# T25 · Run a Fargate sandbox canary

**Depends on:** [T16](T16.md), [T17](T17.md), [T22](T22.md), [T23](T23.md). **Baseline:** no live Fargate runner evidence in the repository.

## Prerequisites

Use an approved isolated cluster, exact task definition and runner image, scoped task/execution roles, private subnets/security groups, sufficient IP capacity and a disposable GitHub selector. Record controller host mode separately. Record platform/architecture, boot protocol, CPU/memory, approved egress and log/scratch behavior, limits and cost/time envelope. Name owners for test shutdown and approved cleanup. Use compatible jobs with no Docker daemon dependency.

## Test runs

| Case | Procedure and expected observations |
| --- | --- |
| Preflight | Read specified cluster/revision and roles, check private networking and quotas. Try an incompatible revision with wrong role, sidecar or unsupported settings on isolated fixtures. Its profile remains unavailable, with no launch or admission. |
| One task, runner and job | Submit one compatible workflow with exact selector. Capture the count-one request, allocation and task identity, handoff, readiness, job completion, log flush and essential-container exit. There is no long-lived runner service and no second launch/offer for the same allocation. |
| Real task-role isolation | Use two live task credentials. Prove own hello and offer access and denial of peer offers, lifecycle rows and administrative credentials. Trace how AWS identity maps to the partition. Verify job processes cannot recover plaintext JIT even if able to access their task credentials. |
| Replay and stopping | Drop the launch response on an approved operation and measure task readback/event timing. Replay only identical parameters/token within the persisted deadline. Use bounded fault fixtures for expired tokens and verify no launch after expiry. Record which behaviors were actually observed live. |
| Early failure and eventual consistency | Exercise immediate essential-container stop, stale/missing task lookup and duplicated or reordered status events. Confirm terminal evidence persists independently of ECS retention and unsettled effects block unsafe competition. |
| Owner replacement and cleanup | Replace the controller while a task executes. Verify exact previous task/process fencing and recovery before new writes. The runner task survives, finishes and cleans up. Stop only an exact provably safe task; deliberately ambiguous or busy tasks are protected. |
| Workload boundary | Confirm selected unprivileged workflows, networking/auth for required endpoints, log delivery and approved scratch. Show a daemon/privileged workload is routed away or rejected by the configured profile contract. |

## Exit criteria

Record exact revisions, approved topology/roles, observed IP/quotas/CPU constraints, job and task event evidence, attempts/time windows, IAM deny proof, drift and host replacement outcomes. Keep any unproven role resolution or retry assumption gated. Verify cleanup of disposable tasks and residual offers after quiescence. Link the preceding `make check` and credentialed integration evidence separately.

Use the T23 harness. Verify actual STS `UserId` from two task identities against the short task-ID derivation and repeat after a controlled role change. From the workflow verify denied peer offer/lifecycle/admin-secret access and denied status writes, even with task-role credentials. Verify no readable JIT in runner process input, environment or scratch. Tests use controlled probes and record only pass/fail and sanitized request IDs. Confirm exact ECS `STOPPED` is persisted without treating exit status as GitHub job success. Record the observed token window and clock margins, and preserve unknown launches if the tested profile's guarantees differ.
