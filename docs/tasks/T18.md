# T18 · Compose shared CDK infrastructure and conditional backend integration

**Depends on:** T03 and the inventory and policy contracts in [T12](T12.md) and [T15](T15.md). **Baseline:** a config compiler and toolchain synth exist. The production CDK entry point and stack do not exist yet. [CDK composition](../implementation-plan.md#4-cdk-composition-and-deployment-ownership)

## Inputs and outputs

Input is a validated environment YAML with explicit account/Region, host, table mode, profiles and referenced AWS resources. Use the compiled runtime artifact and digest from the existing emitter. Build a standalone CDK entry point under `cdk/bin/` and resource composition under `cdk/lib/`. Output the runtime artifact identity and delivery location, roles and policy references, tracking table identity, and any selected queues/clusters. Stable logical IDs and asset contents must not depend on YAML profile order. CloudFormation synthesis requires supplied resource attributes and works with no AWS lookups.

## Implementation slices

1. **Shared resources and import checks.** Create one encrypted retained DynamoDB table in create mode, with `PK`/`SK`, sparse `due` GSI on `dueShard`/`dueAtMillis`, key/scheduling projection, numeric `expiresAt` TTL and PITR. Confirm the projection supports the actual query paths and excludes secret material. Import mode references the supplied table; it performs no mutation. Provide an operator preflight for schema/index, TTL, encryption, PITR and single-Region writes. Pin the runtime asset to digest and trusted generation. Capture rollback and retention requirements before generating host startup metadata.
2. **Resource selection.** Derive selected runner backends from active or draining profiles and hosting from its own selector. Import VPC, subnets, security groups, ASG and task definition by supplied attributes. Create only referenced create-mode cluster entries and deduplicate a cluster shared by host and runner. Keep runner tasks standalone. Per backend, add EventBridge rules with precise resource filters, SQS delivery, retry/redrive and a DLQ as applicable. Document event schemas and delivery permission conditions. Baseline ASG uses notification and polling, creating no lifecycle hook on the imported ASG. Separate malformed/foreign event handling from valid wakeups.
3. **IAM and secrets.** Separate controller runtime, execution, bootstrap and deploy/operator identities. Generate exact active GitHub secret ARN grants and KMS access only where required. Scope ASG writes to configured groups. Scope ECS launch to task revisions and intended clusters, stop to owned tasks and supported conditions, tagging to launch, and `iam:PassRole` to the selected roles with the ECS service condition. Justify every wildcard-only read. Generate bootstrap conditions from T11, either attach approved policies to explicitly managed roles or output policy for the owner. Dry-run permits immutable config/snapshot reads and optional selected inventory reads, plus logs/telemetry. Exclude secret-value reads, lifecycle writes, queue consumption, role passing and provisioning. Protect log contents and set retention, alarms and redrive visibility.
4. **Retirement, retention and rollback.** Before a CDK change removes resource bindings or permissions, verify the durable current generation, two recent complete observations, quiescence and tombstone gate from T10. Provide a preflight interface for an operator/CI flow with explicit account and digest. An environment-only YAML change cannot bypass proof. Continue to grant required accesses to draining profiles. Implement history retention for settled inbox, job and acquisition records after the replay/incident horizon. Keep claims, tombstones and unresolved records durable, preserve replay safety with physically present expired rows, and verify progress under index lag. Define how downgrade and restore preserve leases and conditional checks.

## Acceptance cases

| Case | Required result |
| --- | --- |
| Table create/import and versioned config | Exactly one owned table for create and zero for import. Inspect key and index schemas, encryption, PITR, retention, TTL, grant scope, asset digest/version and stable IDs across reordered YAML. An incompatible import fails preflight. |
| ASG-only, external/dedicated EC2 | No ECS clusters, task definitions, services, ECS provisioning actions, or runner task event rules. Imported ASG/template remains outside CFN ownership. |
| ECS-only and mixed | Fargate-only has no ASG grants/rules or launch dependencies. Mixed includes only selected resources. Imported task definitions, cluster and VPC remain outside CFN ownership. |
| Cluster permutations | Host-only, runner-only, shared and separate, with import/create as applicable. Exactly one CFN cluster per distinct referenced create entry. Unused entries do not synthesize clusters. |
| Retiring profiles and dry-run | Premature deletion, pending work and stale proof block permission removal. Verified retirement removes only the retired bindings. Inspect separate dry-run IAM for prohibited actions and resource references. |
| Events and lifecycle retention | Exact filters, queue source conditions and DLQ configuration. Verify lost/duplicate event and lagging-index recovery via polling. Verify settled history retention boundaries and durable unsettled records. |

Review template diff against a known sandbox baseline before deployment. Validate actual owner permissions and condition keys in [T24](T24.md)–[T26](T26.md).
