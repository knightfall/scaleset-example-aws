# T24 · Run an existing-ASG sandbox canary

**Depends on:** [T13](T13.md), [T14](T14.md), [T22](T22.md), [T23](T23.md). **Baseline:** no live ASG lifecycle evidence in the repository.

## Prerequisites

Use an approved disposable or dedicated canary group and isolated GitHub selector. Record group ARN, AWS account/Region, approved AMI and pinned template, roles, boot protocol, group limits, tested capacity units, policies, protection, workload/OS and owner. Prefer on-demand instances for preservation testing. Set a cost/time envelope and name the person who can stop the experiment and restore owner-managed settings. Snap baseline desired capacity and inventory. Keep production ASGs, launch templates and routing outside the canary change set. [ASG cases](../implementation-plan.md#10-test-matrix-and-acceptance)

## Test runs

| Case | Procedure and expected observations |
| --- | --- |
| Legacy incompatibility | Compare a group with persistent or ordinary group-registered ephemeral runners and a missing/unapproved boot path. Report preflight blockers. Observe zero controller admission, JIT and ASG mutations for that group while existing jobs remain under the legacy owner. |
| Compatible zero-instance group | Verify pinned empty group with supported launch/protection path, then submit a uniquely scoped job. Follow assigned demand, desired units, provisioning, exact instance handoff, runner readiness, one job and process exit. Record desired, pending, registered and busy as distinct observations. |
| Real AWS identity | Use two real instance identities. Prove each can write only its own hello and consume only its own offer, cannot read lifecycle rows/admin secrets and cannot impersonate the peer using different payload fields. From the job runtime, verify protection of IMDS and registration input. Confirm a reboot cannot start a second job with the same allocation. |
| Accurate scale-in | Exercise decrement to exact target and MinSize equality, with spare and busy members. At the floor exercise replacement of a spent exact instance with no decrement. Capture activities and membership, including other AZs. Only tested supported fixed weights may enable decrement. Record actual decrement, replacement and protection; keep unsupported groups report-only. |
| Drift and recovery | Introduce an approved incompatible setting or simulate read/notification failure. Confirm writes freeze and completion observations continue where safe. Drop a scale mutation response and verify exact effect recovery and wire count. Verify polling catches missed notifications. |
| Active job preservation | Restart/replace the controller during a long-running test job. Demonstrate the old process is fenced and the successor recovers with the same executor and no second offer. Unknown or running instances remain untouched, and the job completes. |
| Profile drain | Turn off new acquisitions, finish assigned work, keep physical floor capacity parked only if verified unregistered, and require both clear passes before deleting grants. Show ownership is handed back before any legacy writer restarts. |

## Exit criteria

Collect sanitized job URLs, image/template versions, timeline of provider observations and lifecycle effects, per-instance IAM allow/deny evidence, receipt/call counts, audited capacity transitions and residual resources. Retest affected behavior for platform and group variants declared supported, including relevant Linux/Windows and OS-specific Docker workload paths. Keep incompatible or untested modes gated. Return approved canary resources to their original state after confirming no active work. Run `make check` before the canary and link its run with the integration evidence.
