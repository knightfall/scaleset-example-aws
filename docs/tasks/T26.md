# T26 · Verify mixed operation, dry-run, recovery and rollback

**Depends on:** [T24](T24.md), [T25](T25.md) and the synthesized matrix in [T22](T22.md). **Baseline:** offline behavior and toolchain synth are in place. No complete sandbox deployment/rollback proof.

## Prerequisites

Use approved disposable infrastructure with distinct deployment identity, test set names, profiles and credentials. Save runtime generation/digest, image digest, deployment and tracking-table topology, change-set baseline, role policies, log/trace destinations and prior versions with state compatibility notes. Include a long-running task and instance job for preservation tests. Obtain approval for replacements, rollback or restore exercises. Run the offline suite before a live operation.

## Evidence matrix

| Exercise | Procedure | Pass evidence |
| --- | --- | --- |
| Host and capability independence | Run ASG-only, Fargate-only and mixed profiles against applicable host fixtures and selected actual sandbox host variants. Use the same image digest in supported architecture and config semantics on external Docker, dedicated EC2 and ECS. Deny or make unavailable the unselected backend. | Startup and supported jobs succeed with only selected privileges. One failed profile does not prevent other listeners/reconcilers making progress. Compare offline coverage and actual host cases explicitly. |
| Read-only dry-run | Use the emitted read-only role, with no demand, snapshot and replay. Check optional AWS inventory, versioned S3 delivery, partial reads and simulated restart. Compare audit/API traces around runs and verify no GitHub session or credential calls. | Read-only evidence of deficits, unknown demand/orphans and denied unapproved calls. Zero lifecycle writes, queue consumption, admission, secret retrieval, provisioning, cleanup, or changes to production sessions. Record the audit policy/window and what it can observe. |
| Clean and unclean takeover | Demonstrate clean SIGTERM/session closure, then suspend the former controller before dispatch and run beyond lease expiry in the sandbox. Verify the successor remains in recovery until independently confirmed prior-owner process/task stop or dual-surface isolation and ambiguous effects readback. Test clock-margin loss. | Epoch/owner timeline, request counts and positive host evidence. Stale owner cannot commit and no conflicting external dispatch occurs. Active jobs continue. Unproven fencing blocks activation. |
| Table recovery | Restore a backup into an approved isolated table; verify schema/PITR/TTL, stale generation and ownership behavior, delayed index/TTL and outstanding-operation reconciliation before writes. | Recovered ledger is not treated as GitHub truth. Re-verify actual provider resources and session state. Retain uncertain work and claims. No duplicate allocation or unsafe cleanup. |
| Config, rollback and import safety | Add configured profiles by YAML alone. Drain/remove a profile through actual permission preflight. Verify template and reviewed change-set diff. Revert to compatible image/config using a valid current rollout generation and preserved bindings. Exercise a blocked unsafe rollback. | Runtime/image digests and changeset links. Existing ASGs, VPC, table imports and other owner resources remain intact. Runtime table/assets remain recoverable. Runner work survives. An old config generation or unresolved external side effect is not undone by CFN rollback. |
| Operations | Introduce rate limiting, denied credentials and missing inventory. Verify health/readiness, metrics, log redaction, alert routing and per-profile degradation. | Operator can identify failed dependency and safe next action. No token, payload or private queue URL in telemetry. Recovery after validation resumes only affected work. |

## Exit criteria

Publish expected and observed results, exact matrix coverage, missing cases, approvals, recovery timelines, deployment and job links, policy/audit evidence and residual resources. Document unresolved limitations as production gates. Include `make check`, strict matrix synthesis and the approved validation commands actually run, distinguishing the live read-only checks from fixture guarantees.
