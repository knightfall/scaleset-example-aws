# T11 · Secure a one-job JIT handoff

**Depends on:** T07, T08 and the dispatch boundary from [T10](T10.md). **Baseline:** pinned SDK JIT and DynamoDB handoff wire fixtures exist. No production handoff path is wired.

## Deliverable

Issue a single encrypted, expiring JIT offer to one authenticated executor incarnation. Keep GitHub App keys, PATs and their exchanged tokens in the controller. Keep plaintext JIT out of DynamoDB, AWS resource definitions and logs. [Security design](../implementation-plan.md#7-secure-bootstrap-iam-and-operations)

## Handoff sequence

1. Read a hello scoped to the AWS-supplied identity. Verify its protocol, profile, provenance, boot nonce and ephemeral public key against the selected role and observed provider resource. Bind one allocation to the exact EC2 lifetime or ECS task lifetime under the lease. Repeated or changed hello input must not yield a second allocation. Caller-supplied resource or role IDs do not prove identity.
2. Persist a deterministic runner name and a fenced JIT intent. Use the official scale-set SDK and a single wire attempt. Correlate returned or looked-up identity to the exact set and allocation before delivery. If the response drops after possible issuance, record uncertainty and look up the deterministic name. A runner reference cannot recover lost plaintext, prove readiness or authorize another mint.
3. Encrypt to the verified ephemeral key using a reviewed authenticated envelope and bind scale set, allocation, resource incarnation, boot nonce and expiry. Publish the encrypted offer and matching release evidence atomically. Define sanitization, key lifetime, size limits and behavior when the write acknowledgement is lost.
4. The bootstrap consumes its own offer with a conditional delete returning the old ciphertext, verifies bindings and expiry and decrypts in memory. The controller can conditionally revoke an unconsumed offer. If consumption may have happened, protect the executor. Ignore physically present expired records, and treat TTL as a backstop. A restarted bootstrap or a lost consume response must fail closed.
5. Allow bootstrap only its own hello write and offer consume, scoped by immutable AWS identity via `dynamodb:LeadingKeys`. Prove the mapping with real identities in the backend canaries. Block rollout if AWS identity cannot enforce this boundary. Keep controller and workflow credentials separate.

## Records and authorization

The hello carries protocol version, claimed resource identifiers for comparison, boot nonce, public key and request lifetime. The trusted partition is based on the authenticated AWS principal, with the profile/resource binding verified independently. A controller-side allocation and runner binding are durable before the release of an offer. Use `HELLO#<aws:userid>` and `OFFER#<aws:userid>` as specified in the plan. The offer contains authenticated ciphertext and enough version/expiry metadata to enforce consumption. Keep exact offer and allocation correlation, but no recoverable plaintext, on lifecycle records, projections or diagnostics.

Only the observed executor's validated role and lifetime may release a credential to its bootstrap. Specify the atomic authoring and revision conditions for publication. The revoke and consume predicates must refer to the same offer incarnation. One wins. A new publish must not overwrite an already released or consumed allocation. On release confirmation loss, inspect durable release and offer state without minting again. The execution permission expires even when DynamoDB has not removed the record. Confirm how the pinned runner reads JIT and what job code can observe before declaring a platform supported.

## Implementation slices

**T11a · SDK and storage boundaries.** In `githubsets`, use the pinned `GenerateJitRunnerConfig`, `GetRunner`, `GetRunnerByName` and `RemoveRunner` methods. Check integer conversions for set/runner IDs. Preserve safe classifications for runner already exists, not found and job still running, plus retry hints. Verify the pinned SDK's error identifiers and wrapped errors. A generic 404 on a different resource or scope cannot prove this registration absent. Apply one wire attempt to non-idempotent sends. Keep the `RemoveRunner` path behind T23's scheduling tests for connected idle runners.

Keep bootstrap `PutItem` and `DeleteItem(ReturnValues=ALL_OLD)` on narrow capabilities under a separate bootstrap identity. The lifecycle store currently accepts ordinary lifecycle partitions only. Add explicit typed handoff storage using the same table and the lease/revision transaction boundary, without making arbitrary principal partitions valid for all lifecycle records. The controller uses strong exact-key lookup and fenced offer publication/revocation. Confirm from Go SDK contract tests and live IAM that operations on a peer partition, a lifecycle record or Secrets Manager are denied.

**T11b · Protocol and atomic transitions.** For each observed resource, resolve the verified bootstrap role to its immutable `RoleId`. For EC2 resolve the instance profile ARN with `GetInstanceProfile`, then use `GetRole`. For ECS compare the exact task-definition role and resolve it with `GetRole`. If T24/T25 prove the expected `aws:userid` mapping, construct it from the role ID and AWS-issued **short instance/task ID** and make one strongly consistent `GetItem` for `HELLO#<expectedUserID>/BOOTSTRAP`. The canonical resource ARN belongs in the binding, not the principal suffix. Never trust the hello's claimed ID to choose the key. Role changes, guessed session names and unverified mappings cannot offer credentials. After a role-ID mismatch, resolve the configured role again using the observed binding, keeping issuance closed until verified.

Use a versioned envelope with X25519 ephemeral agreement, HKDF-SHA256 and AES-256-GCM in pinned Go's standard library. Each seal uses a fresh sender key and cryptographically random nonce; reject unsupported versions, invalid keys, all-zero shared secrets, malformed lengths and expired offers. Bind a protocol domain and the canonical version, deployment, profile, scale set, allocation, resource ARN, incarnation, AWS user ID, boot nonce, offer ID and expiry as authenticated context. Define an unambiguous field encoding and test vectors before implementation. The wire envelope carries the sender public key, nonce and ciphertext. Keep ephemeral private keys and JIT only in memory. Review the envelope and runner input path before live use.

Use one durable allocation claim per resource lifetime. Persist the expected runner identity/name and immutable JIT intent before the request. On receipt, validate the exact returned identity and write the runner association, lookup mapping and offer release as a single fenced transaction with the encrypted offer, or bind first and condition publication on that exact committed binding. Derive the offer ID deterministically from the hello's random boot nonce with a versioned domain, so the bootstrap can conditionally consume its exact offer without a read grant. A consume checks offer ID, boot nonce and expiry and atomically deletes the matching item. The bootstrap still verifies expiry after receipt. Revocation deletes that same incarnation and records revocation in the same transaction. A missing item without proof of prior revocation is ambiguous; no retry may publish another offer. Preserve the release flag across restart so a deleted item cannot reset an allocation.

## Fault cases

| Fault | Required result |
| --- | --- |
| Spoofed resource ID or changed nonce/key for a bound resource | No new allocation, runner mint or offer. Record sanitized conflict evidence and protect existing work. |
| Lost JIT response after remote commit | One request. A later runner reference can identify the registration only. Preserve uncertainty and use an approved reconciliation path before issuing credentials to another allocation. |
| Process death after JIT issuance but before offer publish | Plaintext stays lost across restart. Durable intent and lookup evidence protect the allocation from a second mint. |
| Publish receipt lost or duplicate delivery | Read back exact release evidence. Do not issue another JIT or overwrite a released offer. |
| Concurrent revoke and consume | Exactly one transition wins. Revocation evidence can prove unused only if consumption was excluded. A lost consume receipt must not authorize re-consumption or cleanup. |
| Wrong recipient, tampered envelope or expired item remains visible | Reject before starting the runner. Exclude peer access by policy and reject wrong binding cryptographically. |
| Exit report forged by job code | Cannot establish terminal process evidence or authorize cleanup. Preserve protection if authenticated exit is unavailable. |

## Review decisions

For EC2, T14 may publish a dedicated `STATUS#<aws:userid>` item scoped to the allocation only after the supervisor's credentials and reporting path are isolated from workflow code. Grant that action only to the proved EC2 bootstrap identity. Fargate receives no status-write grant. Use exact ECS terminal task evidence plus independent GitHub job and registration evidence. Keep Fargate readiness unknown absent a trusted readiness source. A stopped task proves the task ended, while its exit code alone establishes neither job completion nor registration cleanup. Review protocol lifetime and runtime identity assumptions with T24/T25. If job code can publish an authoritative state, block the affected path.

## Acceptance

- Wire fixtures prove one JIT request after simulated server commit and dropped response. Unknown registration, wrong set/runner/incarnation and delayed lookup do not mint a replacement or permit cleanup.
- Tests cover offer publish and resume, duplicate hello, malicious rebinding, wrong nonce/address/key, ciphertext modification, malformed or expired offer, consumption/revocation races, lost receipt and reboot. Only one winner may obtain the offer. Terminal state is durable across restart.
- Scan mocked persistence, error messages and structured logs for synthetic secrets and plaintext JIT. Demonstrate no job process can recover registration input from the pinned launch path. Do not use real secrets in fixtures.
- Run `go test -race ./tests/lifecycle ./tests/sdkcontract` and `make check`. Link reviewed protocol and role policies. Confirm peer denial and per-executor identity on actual EC2 and Fargate in [T24](T24.md)/[T25](T25.md) before enabling each backend.
