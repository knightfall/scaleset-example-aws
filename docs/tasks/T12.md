# T12 · Preflight and inspect an existing runner ASG

**Depends on:** T04, T05 and the inventory/dispatch boundary in [T10](T10.md). **Baseline:** AWS SDK wire fixtures and client constructors exist.

## Deliverable

Map the configured ASG ARN and owner-approved bootstrap contract to a read-only provider snapshot. Give listeners a verified capacity limit only when the group is eligible. [ASG design](../implementation-plan.md#asg-adapter) · [AWS SDK fixtures](../../tests/sdkcontract/aws_test.go)

## Adapter contract

Input is a validated `asg` profile, current inspection deadline and the configured account/Region. Resolve the ASG name from the canonical ARN, then verify the ARN returned by AWS. Preserve both IDs through request and observation translation. Use the adapter's normalized inventory for `reconciler.InventoryProvider`, and share read-only evidence with preflight/dry-run. Retain a sanitized canonical reference and timestamp for each observation. Keep AWS response types outside planner and lifecycle decisions.

| AWS facts | Interpretation and expected output |
| --- | --- |
| Matching group ARN and complete membership, no instances | Known empty inventory. Capacity limit is separately verified from the compatible launch envelope. |
| Name matches, ARN changed | Binding drift. Nothing may adopt the replacement. Report identity mismatch and no capacity authority. |
| AWS intends a launch/replacement but there is no verified executor | Reconcile intended physical capacity to avoid another desired increase. Do not count a registered/serving runner. |
| Instance exists but provenance, state or bootstrap is unverified | Record unknown occupancy and reason. Never mark a missing or restartable instance irreversibly gone. |
| Exact instance irreversibly terminated | Candidate terminal observation only with evidence for this incarnation, independently of GitHub registration readback. |
| Unsupported policy, role/template drift, health or dependency failure | Keep unresolved state distinct from zero and surface blockers. Freeze this profile's writes. |

Record how the adapter verifies bootstrap compatibility for an empty group, launch-template versions in mixed-instance policies, known weights, externally managed protection and absence of competing desired-capacity writers. A config label or tag alone cannot prove a launched image runs the required one-job bootstrap.

## Requirements

- Resolve exact group ARN, account, Region, current min/max/desired units, actual members, launch templates and versions, AMIs, instance types, launch roles, protection defaults and health/lifecycle states. Read relevant activities, policies, scheduled actions, refresh and warm-pool configuration. Follow pagination and reject partial, contradictory or unauthorized lookups.
- Verify homogeneous approved platform, one-job JIT bootstrap and ownership. A normal persistent runner, a legacy ephemeral group registration, or unverified launch path contributes no scale-set capacity. Require an approved bootstrap version and canary evidence before active adoption. Never mutate the launch template or imported group.
- Separate group desired units, pending or replacing capacity, actual inventory, observed runner readiness and unavailable capacity. Report unsupported desired unit types and varying weights as report-only. Convert homogeneous fixed weights only when the configuration and live launch candidates agree.
- Admit an empty compatible group as known zero current occupancy with a separately verified capacity limit. Incompatible preflight prevents acquiring jobs, issuing JIT and changing capacity. If drift occurs after activation, freeze these writes while preserving running work and receiving valid completion evidence; other profiles continue.
- Return canonical resource identity and incarnation signed off by the provider/bootstrap design. Preserve unknown membership or incarnation on ambiguous reads. Expose the same inventory facts to authorised dry-run without requiring any mutator.

## Acceptance

1. SDK fixtures exercise wrong ARN, deleted/recreated same name, no access, incomplete pages, stale observations, incompatible legacy setup, unsupported weights/units, warm pool or refresh, and competing policies. Assert no AWS writes occur.
2. Distinguish absent/unknown from empty compatible, pending replacement from ready, and verified no capacity from unavailable limits. Prove bootstrap and protection drift block only the affected profile and that unrelated ECS configuration is never required.
3. Run `go test -race ./tests/sdkcontract ./tests/lifecycle` and `make check`, including focused adapter tests in the implementing PR. Verify user-owned launch compatibility and legacy drain evidence in [T24](T24.md).
