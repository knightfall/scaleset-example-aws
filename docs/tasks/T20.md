# T20 · Deploy dedicated controller EC2 hosting through CDK

**Depends on:** [T18](T18.md), [T19](T19.md). **Baseline:** the schema supports `ec2`; no hosting resources exist.

## Deliverable

For `spec.controller.hosting.type: ec2`, synthesize dedicated controller EC2 capacity with systemd-managed Docker, independent of every runner ASG and runner provisioner. Import supplied VPC, subnets and security groups, and use the approved AMI and instance type. Select the host subnet according to validated inputs and document the resulting placement, reachability and ownership.

## Requirements

- Compose the dedicated instance, restricted role/profile, encrypted root volume, required IMDSv2, private networking and log delivery. Scope config reads and registry access. Ensure bootstrap can install or use the approved Docker runtime and produce a diagnosable failure if image/config cannot be verified. Use explicit approved artifact digest and generation. Keep secret values out of user data and CloudFormation output.
- Start the image under systemd with least host/container privilege, a read-only config mount, bounded restart/backoff and stop timeout, private probes, and no public management access by default. Specify health behavior if Docker, credentials or egress fail. Image pulls and config access use host identity. GitHub secrets are fetched by the active app.
- Generate process-specific lease ownership. Stop and verify previous container/process group before a controlled replacement. For unclean loss, require proof of exact host/process stop or isolation from both AWS and GitHub mutations. Do not treat instance status, health-check failure or elapsed lease alone as sufficient fencing. Document time-source/clock-skew check and apply bounded request deadlines.
- Rollback must respect the current table schema, catalog generation and active runner state. Preserve supporting resources if a host fails. A stopped/replaced controller host must not terminate or reconfigure runner ASGs.

## Acceptance

| Scenario | Required proof |
| --- | --- |
| EC2 with ASG-only, Fargate-only and mixed profiles | Exactly the controller compute and selected runner integrations. No controller ASG and no unexpected runner resources. Inspect operating system, block device, public-IP and metadata settings, policy and systemd/user-data for exact configured artifact references. |
| External and ECS host selected | Dedicated instance, profile and EC2 host bootstrap are absent. Fargate-only on EC2 omits runner Auto Scaling grants/integrations. |
| Restart/upgrade/rollback | Smoke test missing asset, digest mismatch, startup retry, config mount, IMDS access and private probes. Verify old controller quiescence, bounded shutdown and preserved runner work in the T26 sandbox. |

Run `make check` plus [T22](T22.md) strict offline synthesis. Record actual boot and lifecycle evidence from [T26](T26.md), including fault handling and exact host fencing.
