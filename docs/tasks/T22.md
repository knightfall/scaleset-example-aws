# T22 · Verify the full offline CDK resource and IAM matrix

**Depends on:** [T18](T18.md), [T20](T20.md), [T21](T21.md). **Baseline:** config validation and private toolchain fixture synthesis exist. This task exercises actual controller infrastructure. [Required test matrix](../implementation-plan.md#10-test-matrix-and-acceptance)

## Deliverable

Add an ordinary CI suite using the real CDK entry point and fixture YAML. Synthesize without account credentials or context lookups. Assert resource objects, cross-resource references, policy statements, conditions and stable logical IDs. Report exercised rows and intentionally inapplicable permutations.

## Matrix

| Axis | Values and assertions |
| --- | --- |
| Runner selection | ASG only, Fargate only, mixed. Include a disabled otherwise unused backend and an enabled draining profile. Assert corresponding adapters, permissions and rules. |
| Host | External, dedicated EC2, ECS Fargate. External emits supporting resources only. EC2 creates dedicated host. ECS creates controller service only. Test external identity variants supported by config. |
| Table | Create and import across the applicable host/backend matrix. Assert exactly one owned table or none, with correct config/read references, index projection, retention and policy. |
| Mode | Active and default dry-run. For dry-run test inspection off and on, no-input and authorized snapshot delivery. Inspect absence of mutator permissions and any GitHub secret-value permissions. |
| ECS cluster | Existing or new for each selected cluster entry. Distinguish host-only and runner-only, shared and separate, including mixed create/import. Omit unreferenced cluster entries. |
| Lifecycle | YAML-only add, active-to-draining, revoke/disable/delete after verified retirement, blocked premature removal, stale version, and last-profile shutdown. Assert no change to unrelated resources and no import replacement. |

Use a table-driven product of applicable dimensions. Include the reason for excluding impossible combinations such as an ECS cluster selection when neither host nor runner uses ECS. Verify authored YAML, resolved artifact and synthesized resources point to the same exact bindings and digest.

In the resource assertions, check exact table name and GSI projection, selected role policies, per-backend event selectors, immutable artifact references and each host's real argument/health/stop values. Test all external identity variants with imported ownership preserved. Exercise erroneous synth and unauthorized retirement as separate cases. Offline fixture evidence must not satisfy live retirement preflight. Inspect negative assertions on IAM actions and conditions as well as resources. Ensure CI actually invokes the real synth matrix once it exists.

## Critical negative assertions

- **ASG-only with external or dedicated EC2 hosting:** zero `AWS::ECS::Cluster`, `AWS::ECS::TaskDefinition`, `AWS::ECS::Service` and runner ECS provisioning permissions or event rules. ASG-only with an ECS host may synthesize only host ECS resources and must omit runner launch/stop grants.
- **Fargate-only on any host:** zero runner Auto Scaling resources, lifecycle hooks, rules or API grants. Dedicated EC2 controller compute remains permitted.
- Imported networks, runner ASG, launch template, table, task definition and cluster are references only. No implicit context lookup, new runner ECS service or unsanctioned IAM mutation to an external role. No dummy identifiers in otherwise absent config.
- Deny invalid/empty config before synthesis, and fail on wrong ownership/generation or missing drain proof before removal. Trust real retirement evidence for deployment. Tests can model its inputs.

## Acceptance

1. Run `npm --prefix cdk run test:synth-matrix` once implemented and `make check`. Preserve appropriate fixture test runtime. Record row counts and output template names. If the new suite is split, include all partitions in CI.
2. Assert resource and statement references as well as names/counts, including IAM separation for active/dry-run, exact service/cluster selectors, redrive and imported identities. Verify logical ID stability under profile ordering and unrelated additions.
3. Inspect read-only template diff for profile add/drain/removal and host rollback. Use fixture input to prove no unintended replacements. [T26](T26.md) verifies change-set and rollback with approved sandbox resources.
