# T19 · Package and run the controller on external Docker

**Depends on:** T04, T07 and [T10](T10.md). Packaging and offline smoke tests can start after the runtime interface is defined. Active release requires adapters, handoff and preflight for the selected profiles. **Baseline:** root CLI has config verification and one-shot offline dry-run, and [image bases](../../build/images.env) are pinned.

## Deliverables

Provide an independent multi-stage Docker build, an active runtime entry point in [main.go](../../main.go), a separate read-only dry-run path and an external hosting runbook. Produce one platform-appropriate image with the same application and config semantics for external Docker, dedicated EC2 and ECS Fargate. Publish immutable image digests and pinned configuration artifacts through the reviewed release pipeline.

## Process and dependency contract

- Validate config and digest and verify trusted generation before loading active dependencies. Use one unique owner per process incarnation and coordinate leases, catalog claims, listener/reconciliation workers and shutdown under one root context. Wire verified capacity into admission and dispatch triggered independently of acknowledgement. Fail closed on bad config or ownership and degrade affected profiles on backend errors. Never require an unselected AWS service.
- Preserve offline `reconcile --dry-run --once` behavior. Supply an explicit, optional read-only path for T12/T15 inventory and versioned S3 input. Configuration identity, digest and snapshot freshness must be checked before use. Build this path without GitHub secret/session clients, mutating store or queues.
- Package the binary with verified pinned bases and approved CA handling. Use nonroot, read-only root filesystem, minimum writable paths, no Docker socket or default public management port. Test ordinary startup, reject missing/tampered artifact, and use a probe compatible with the actual image contents. Keep runtime config/region/identity explicit and avoid baking secrets into layers or arguments.
- Add private liveness and readiness. Liveness reflects process/supervision progress. Readiness distinguishes initializing, usable and degraded profiles, invalid lease/recovery and missing backend capacity. Graceful SIGTERM closes owned sessions after stopping admissions and new dispatch, retains unresolved intents, and leaves independent running jobs alone. Align drain and process-kill budgets with hosting.
- Use structured redacted logs and OpenTelemetry spans/metrics with bounded labels. Record poll progress, demand ages, slot/deficit counts, backlog, startup and handoff times, ownership loss, drift, throttles, orphan/cleanup ages and useful spend indicators. Export to an approved existing sink. Ensure telemetry failure does not stall effect processing or leak payloads.
- The runbook documents existing EC2 IMDSv2/container metadata boundaries, scoped assumed roles where configured, or Roles Anywhere with protected helper and trust material outside EC2. Cover registry access, mounting digest-pinned config, egress, rotation, supervisor restart/backoff, upgrades, quiescence, clock-offset validation, old-process evidence, rollback and on-call ownership. Separate host permissions from runner and deployment permissions.

## Acceptance

1. Build using `docker build --tag scaleset-controller:local .` and the repository's pinned bases. Inspect image configuration and history for no credentials and correct entry point/nonroot user. Run with read-only filesystem, fixture config and constrained network. Verify health and `config verify` from the built image.
2. Test root composition with fake dependencies for each runner combination and both modes. Invalid config and offline dry-run produce zero AWS/GitHub calls. Verify stale generation and uncertain prior ownership block mutation. Invalid backend evidence closes only the affected profile. Test concurrent profile progress and bounded shutdown during a poll and an unfinished effect.
3. Check snapshot error, S3 wrong version/digest and AWS denied responses, with scripted tests that fail on any unexpected secret/session/queue/write request. Confirm report source, freshness, unknown values and orphan classification.
4. Run `make check` and Docker smoke checks on supported build architectures. Record build digest, launch command, probes, bounded stop proof and dependency versions. In [T26](T26.md), run the same digest through the authorized hosts and validate identity, restart and rollback.
