# T17 · Bootstrap one runner on Fargate

**Depends on:** [T11](T11.md), [T15](T15.md). **Baseline:** no Fargate runner entry point or approved task-definition example.

## Deliverable

Provide the runner container bootstrap and documentation for the supplied pinned task definition. Bind one authenticated task lifetime to one JIT executor and exit the essential container after the job and log flush.

## Requirements

- Read the platform metadata and use credentials from the exact selected task role. Match task/cluster ARN, task role identity, allocation, nonce, approved revision and bootstrap protocol with controller-verified provenance. Task metadata or caller-chosen tags alone cannot authorize a handoff.
- Reuse T11's conditional consume and encrypted envelope. Keep keys in memory and deliver JIT only through the pinned runner input. Any process in the task may be able to reach task credentials. Limit them to the task's bootstrap operations. Keep the ECS execution role, controller role and workflow AWS roles separate.
- Run compatible unprivileged workloads. Reject workflows that require a local Docker daemon, privileged containers or unsupported host features; route those to a compatible ASG profile. Avoid sidecars and credential-bearing environment/overrides. Document writable scratch, platform constraints, logs and the essential container exit contract.
- Emit authenticated runner readiness/exit and sanitized failure details. Coordinate with ECS observations for terminal evidence. A lost offer receipt, bad protocol version or duplicate startup fails closed without restarting a spent runner.

## Container contract

Document the exact input subset allowed in the supplied task definition and launch overrides. Allocation ID and private endpoint/config references may be nonsecret inputs. Identity proof comes from verified task metadata, role and controller/provider evidence, not from a caller-asserted environment variable. Registration bootstrap runs before the workflow and retains no recoverable credential files or inherited secret environment. The runner works as a nonprivileged process with bounded scratch space and forwards shutdown signals and logs appropriately.

On startup failure, record a sanitized result and exit the essential container. On success, run one job and finish once. If the job ends but process/log completion evidence is delayed, keep separate timestamps and leave the task protected until the lifecycle and provider gates agree. Reuse the T11-reviewed reporting channel so workflow code cannot forge a ready or exited signal that changes safety. Demonstrate this even when workflow code can use the minimal task role.

Reuse the T14 bootstrap entry point and T11 envelope, with a Fargate mode that validates the ECS-provided v4 metadata endpoint as local and bounded, validates the task metadata and STS `UserId`, and checks canonical task ARN, cluster, definition revision and nonce against the offer. Workflow code may reach the task role. Grant no status writes or AWS/GitHub mutation access to this bootstrap. Use bounded writable scratch and pass signals to the runner child. Treat exact control-plane `STOPPED` as the terminal **resource** observation and retain job/registration evidence separately. Keep process readiness unknown unless trusted evidence or the exact running job proves it. A container-supplied status or zero exit code cannot establish completion or cleanup authority.

## Acceptance

1. Fixture-test missing or mismatched task metadata, role identity, task revision, duplicate bootstrap, offer expiry, lost consume response and one session per allocation. Assert no file, environment, logs or job input exposes the credential.
2. Exercise one-job execution, essential-container exit and log delivery using the supported image path. Verify the supplied definition satisfies T15 and the runner behavior does not rely on ECS Exec or privileged runtime features.
3. Run `make check` and concrete bootstrap/container smoke tests added with the implementation. Demonstrate real role isolation, no peer offer consumption and a completed compatible workflow in [T25](T25.md).
