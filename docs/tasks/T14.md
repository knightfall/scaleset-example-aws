# T14 · Bootstrap one runner on EC2

**Depends on:** [T11](T11.md), [T12](T12.md). **Baseline:** no EC2 runner bootstrap implementation.

## Deliverable

Provide a versioned bootstrap entry point and owner installation instructions for an approved existing ASG launch path. Verify the running instance's identity, claim one JIT offer, run one job and retain authenticated readiness/exit evidence.

## Requirements

- Resolve the instance using IMDSv2 and its scoped role session. Tie the hello to current instance lifetime, ASG membership, expected protocol, role and approved image/template. The controller must verify protection and provenance before delivery. A reboot is never permission to mint a second runner on a spent instance.
- Consume the encrypted offer via T11. Invoke the pinned supported runner integration with ephemeral JIT. Run exactly one job under the chosen non-administrative runtime identity. Protect bootstrap credentials, process arguments, metadata endpoints and files from job code, including applicable Linux/Windows and Docker execution.
- Authenticate readiness and terminal process evidence to the same allocation and runner identity. Ship sanitized diagnostics and flush logs. Distinguish startup failure, process exit, job completion and instance termination. Do not let a local exit alone authorize ASG termination.
- Keep launch-template and legacy runner service changes in the ASG owner's workflow. Document compatible Linux/Windows, OS-specific Docker and Copilot profile requirements. Persistent registration and legacy service startup are incompatible with this bootstrap until migrated.

## Bootstrap sequence and failure return

| Stage | Inputs and required result |
| --- | --- |
| Start | Read approved protocol/config and AWS-generated identity before creating a hello. Fail closed for missing metadata, role drift or a restarted spent instance. Pin runner artifact/version and approved verification method. |
| Wait | Poll or consume the exact role-scoped offer within a bounded time. Keep keys memory-only and expose sanitized timeout/degradation. A failed or lost consume does not publish a fresh hello that could mint another credential. |
| Execute | Clear unnecessary bootstrap identity access from the runner/job trust boundary. Invoke the pinned supported ephemeral runner and report readiness only after verified connection. Preserve startup, ready and exit as separate observations. |
| Finish | Flush diagnostics then report exact authenticated process exit or failure. Preserve the process result independently of job completion and provider terminal state. Never invoke ASG APIs from bootstrap. |

Provide the owner an installation/version manifest and a rollback procedure that restores the prior boot mode only after confirmed drain and handback. Demonstrate platform-specific boundaries for host-level processes, containers and process arguments, including the Linux and Windows variants declared supported. Wire readiness and exit to the verified reporting channel reviewed in T11. Job-controlled output or access to a role scoped for hello/consume cannot authorize a terminal process transition.

## Acceptance

1. Exercise simulated metadata and SDK identities, denied/expired credentials, wrong instance/role/AMI, unprotected instance, protocol mismatch, consume/restart races, bad offer and second invocation after a job. Assert no second registration and authenticated failure visibility.
2. With the pinned runner version, verify one-job invocation, log redaction, permissions on transient inputs, graceful exit and credential absence at workflow start. Test image/platform-specific paths before declaring support.
3. Run `make check` and the bootstrap fixture suite added by this task. The [T24](T24.md) canary must prove metadata and offer isolation, one job and safe ownership handover before enabling the group.
