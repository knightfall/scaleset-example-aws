# T15 · Preflight and inspect Fargate runner execution

**Depends on:** T04, T05 and the inventory/dispatch boundary in [T10](T10.md). **Baseline:** ECS SDK wire fixtures and conditional client creation exist.

## Deliverable

Report read-only Fargate runner eligibility and inventory for exactly the cluster, task-definition revision, network and roles selected by each enabled profile. Host cluster selection is independent. [Fargate design](../implementation-plan.md#fargate-adapter)

## Requirements

- Verify canonical cluster and task definition ARN, pinned revision, Fargate compatibility, `awsvpc`, approved platform and CPU/memory, exact task/execution roles and supplied network. Inspect available limits and placement evidence. If quotas, available IPs or capacity cannot be justified, keep actionable backend limits unknown.
- Require the single approved essential runner container. Check image digest, entrypoint, command, restart policy, log/scratch setup, mounts, environment and secret reference contract. Reject privileged or Docker-in-Docker workloads, sidecars, ECS Exec and overrides or role grants inconsistent with the one-job trust boundary.
- Query and paginate owned task observations. Verify exact cluster/task identity, allocation provenance and task revision. Treat unrelated tasks as unknown/orphan candidates only when in the relevant inventory scope, and account for verified occupancy. Missing results, ECS failure entries or eventual consistency cannot prove terminal absence. Distinguish known empty inventory from denied, partial or stale inventory.
- Keep inspection available through read-only dry-run where authorized. Avoid any ECS provisioner or runner preflight when no Fargate profile is enabled. Freeze affected writes on revision, role, networking or provenance drift while other profiles continue.

## Inspection contract

Resolve cluster and network using the artifact's selected entries, with the task definition ARN pinned by revision. Record which capability checks come from `DescribeClusters`, `DescribeTaskDefinition`, network/account inspection, or an approved external limit verified in preflight. Map facts to normalized snapshot completeness, timestamp, limit and exact task identities. Keep raw SDK responses inside the adapter.

| Observation | Required interpretation |
| --- | --- |
| Approved revision, complete empty task set and available headroom verified | Known zero occupied tasks and separately verified positive or zero limit. |
| Matching definition family with a different revision or role | Configuration/provenance drift. No launch/cleanup authority. |
| Partial AWS response, denied quota/network observation or uncertain ownership tag | Preserve unknown limit/occupancy or ownership. No invented zero and no assumed available IPs. |
| Task lookup returns an absence/failure reason | Preserve uncertainty until exact terminal/provider evidence. Record sanitized reason for recovery. |
| Task is foreign to this profile but consumes shared physical capacity | Account for the relevant resource/limit without attributing the task to this profile or authorizing its cleanup. |

Record how the adapter scopes lists and handles all pages without conflating other profiles that use the same cluster and definition. Verify the provenance boundary against untrusted tags and task metadata. Dry-run and active preflight should use consistent interpretation of the same provider facts.

## Selected read capabilities

- Split ASG inventory capabilities from read-only EC2 network and IAM role lookups. Fargate-only may construct `DescribeSubnets`/`DescribeSecurityGroups` and `GetRole` clients for verified Fargate requirements. It must initialize no Auto Scaling client and call no instance or launch-template APIs. Add fixtures that fail on unselected calls and preserve role resolution for both backend types.
- Require exact active cluster and task definition, approved single essential container and task/execution roles. Check `DescribeClusters`, `DescribeTaskDefinition`, effective `taskLongArnFormat` via `ListAccountSettings`, and actual tags/long ARN on readback. Verify VPC, supplied subnet AZs/security groups and private available addresses. Validate runtime platform and all container privilege, mounts, input and restart settings. See [ECS account settings](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/ecs-account-settings.html) and [ECS authorization](https://docs.aws.amazon.com/service-authorization/latest/reference/list_amazonelasticcontainerservice.html).
- In v1 take the approved on-demand vCPU allowance for this environment from current operator preflight evidence rather than adding an unconditional Service Quotas client. Record account/Region, observation/expiry, reserved margin, tested placement and shared-account usage. Compute conservative incremental headroom from verified available IPs and CPU/task allocation, subtracting outstanding launches not yet represented in those observations. Observed free addresses already exclude attached ENIs. Do not subtract those tasks twice. Pass an absolute slot envelope that accounts for already occupied slots and verified additional headroom. Apply shared budgets across profiles using the same pool. Missing or stale evidence keeps the limit unknown and closes new admission. Verified zero headroom remains a known limit.
- Use the exact long task ARN as resource ID and a single versioned encoding of task ARN, exact task definition ARN and durable allocation ID as incarnation. Tags and `startedBy` correlate observations but never substitute for fenced allocation/claim and exact role/provenance evidence. Check a known allocation's described task and preserve exact terminal facts. Paginate cluster-scoped discovery and batch supported `DescribeTasks` requests, checking failures as well as tasks. For T16 correlation use a separate cluster-scoped `ListTasks(startedBy=...)` with no other filters and treat stopped results or events independently. See [ListTasks](https://docs.aws.amazon.com/AmazonECS/latest/APIReference/API_ListTasks.html).

## Acceptance

1. Fixtures cover import/create cluster resolution, wrong cluster/revision/network/role, extra containers, unapproved entrypoint, unsupported workflow, unknown quotas, failed describes, malformed pagination, stopped task and conflicting identity. No `RunTask`, `StopTask` or ASG APIs are called.
2. Verify a supported zero-task cluster differs from unavailable inventory. Confirm stale/incomplete snapshots do not authorize new admission or cleanup and that host-only ECS configuration does not initialize Fargate runner preflight.
3. Run `go test -race ./tests/sdkcontract ./tests/lifecycle` and `make check` with backend adapter tests. Live IAM, platform, available IPs and quota evidence belong to [T25](T25.md).
