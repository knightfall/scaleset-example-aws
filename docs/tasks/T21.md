# T21 · Deploy ECS Fargate controller hosting through CDK

**Depends on:** [T18](T18.md), [T19](T19.md). **Baseline:** schema and config fixtures accept ECS hosting. No production service exists.

## Deliverable

For `spec.controller.hosting.type: ecs-fargate`, synthesize one controller task definition and ECS service using the same verified Go image and runtime artifact. Support an imported cluster or an explicitly created cluster and place the service in supplied existing VPC subnets/security groups.

## Requirements

- Consume the exact configured CPU/memory/architecture, network, image digest and versioned config. Ensure private placement and reachable approved endpoints. Separate ECS agent execution privileges for registry/log access from controller in-process permissions. Keep GitHub credentials and JIT out of task settings. Provide a health probe compatible with the image and sanitized log delivery.
- Use one desired replica, stop-before-start rollout with minimum healthy 0 and maximum 100, and deployment circuit breaker/rollback as planned. Test stop timeout and probe timing against the controller's bounded shutdown. Account for the intentional control-plane gap and preserve independent runner tasks.
- Keep the service and runner launch integration separate. An ASG-only ECS-hosted environment creates controller ECS resources and does not grant runner `RunTask` or `StopTask`. Mixed can share or separate host/runner clusters as configured. Bind exact task identity to each owner incarnation. An ECS task replacement is not sufficient evidence until exact old task termination or equivalent isolation is verified.
- Document scheduler/rollout failure recovery, time-source policy, compatible artifact rollback, retained DynamoDB/config resources and manual recovery when the old task or its effects remain uncertain.

Render the T19 launcher with versioned config identity, verified digest and explicit generation. Set private networking, read-only root filesystem, ECS Exec disabled, a direct `CMD` health check invoking the controller binary and `stopTimeout: 90` seconds. Execute probe in-container on loopback. Allow startup grace consistent with verified config availability and maintain readiness separately. Assert actual stop budget exceeds the total application shutdown budget. ECS replacement records and verifies the prior **controller** task ARN reached `STOPPED`, then still reconciles outstanding effects before mutation. If prior identity or terminal evidence is missing, require approved fencing proof. Do not grant runner launch or stop just to check controller-task state. [ECS Fargate task definition parameters](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/task_definition_parameters.html)

## Acceptance

1. Synthesize imported/new host clusters, ASG-only ECS host, mixed shared cluster, separate host/runner clusters and unselected extra clusters. For import emit no host cluster CFN resource. For shared create emit exactly one. Assert private network and image/runtime links and scoped role separation.
2. Inspect desired count, deployment percentages, circuit breaker, health, stop timeout and log configuration. Test controller exit and asset/identity failure paths without requiring the runner backend. Confirm external/dedicated EC2 synth omits the controller ECS service and task definition.
3. Run `make check` and [T22](T22.md) synthesis. Sandbox test service replacement, active runner preservation, exact prior task proof and rollback via [T25](T25.md)/[T26](T26.md).
