# T13 · Scale ASG capacity and retire exact instances

**Depends on:** T07, dispatch from [T10](T10.md), and [T12](T12.md). **Baseline:** pinned SDK capacity and targeted-termination wire fixtures exist.

## Deliverable

Reconcile approved ASGs to a safe physical target, using absolute scale-up and exact-instance retirement. Leave owner-managed group settings and unknown/active resources protected.

## Requirements

- Compute units from verified instance capacity and fixed supported weight, as applicable. Respect AWS MaxSize/MinSize, configured profile headroom, already intended launches/replacements, and demand freshness. Before issuing `SetDesiredCapacity`, re-read membership, limits and current desired state. Increase only. Freeze if another desired-capacity writer or relevant drift appears.
- Treat one qualified instance as at most one runner slot. Test stop/restart and pending launch behavior. Avoid adding another scale-up for capacity already in flight. No support for translating variable weights, vCPU/memory units or unknown candidates into safe instance counts in the initial release.
- After T10 authorizes cleanup, re-read exact resource and group plus current policy, desired units, min and planned target. Target that instance with `TerminateInstanceInAutoScalingGroup`. Decrement only if the resulting desired units stay at or above the greater of the group floor and planned target. Equality is permitted. A spent instance at the floor may need replacement without decrement. Do not start replacement runners in a drained profile unless assigned demand requires them. Protect other AZ members and verify rebalancing/protection behavior in the canary.
- Persist exact request, including decrement, and disable ambiguous SDK retries for non-tokenized writes. Use activity/membership and desired-capacity readback to resolve. A lost response is not a reason to send the mutation again. Retain or surface unresolved effects before permitting a competing capacity change.

## Request and decision examples

Capacity units are a provider concern. Pass safe runner proposals and verified headroom to the adapter. Return the normalized capacity facts and planned request for reporting and journaling. The dispatch intent identifies profile, exact group ARN, action, target and applicable before-state, including desired/min/max units and exact instance incarnation for retirement. Verify the saved request digest and preconditions before sending it.

| Verified state | Expected decision |
| --- | --- |
| Desired 0, 0 eligible/intended slots, verified demand 2, compatible unweighted capacity | Increase to 2 if cap/headroom and launch policy allow it. Verify no blanket decrease path exists in the same adapter. |
| Desired 2, one registered and one pending member for a target of 2 | Keep desired 2. Pending is not a ready runner. Stalled pending capacity degrades availability without automatically authorizing a second launch. |
| Desired 4, MinSize 2, planned physical target 3, exact completed unweighted member | Target the completed member. Decrement to 3 is eligible because equality at target is allowed. |
| Desired 3, MinSize 3, exact spent unweighted member and explicitly required replacement | Target that member without decrement. A draining profile does not automatically JIT the replacement. |
| Fixed weight or AZ rebalancing impact unverified | Preserve capacity and report the live gate for that scale-in action. Never approximate unsupported unit conversion. |
| Group changed after preflight, instance recently became busy, or write outcome unknown | No competing capacity mutation. Re-read exact identity and state or enter recovery. |

For each API, name the observed result that confirms it took effect and the evidence that can establish it did not. A desired value that another writer could set, or an instance absent from an incomplete response, is insufficient attribution. Do not settle a request that may still apply after the current observation.

Fake and SDK transport tests cover zero-to-demand, slow bootstrap, in-flight replacement, cap/weight rounding, exact target/floor, replacement at floor, unknown group or job, wrong membership and changed desired state before send. Assert the target parameters and absence of writes on unsafe evidence.
2. Simulate commit then dropped response for both APIs. Confirm one wire attempt, unchanged intent target and successful or blocked recovery based on exact evidence. Verify no blanket reduction via `SetDesiredCapacity`.
3. Run `go test -race ./tests/sdkcontract ./tests/lifecycle ./tests/reconciler` and `make check`. Enable fixed-weight scale-in only after [T24](T24.md) proves actual decrement, protection and rebalancing for the selected group.
